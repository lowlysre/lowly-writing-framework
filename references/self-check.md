# Self-check before finishing

The shared checklist for every artifact this skill governs: PR bodies, issue bodies, discussion posts and comments, PR review comments, docs, code comments. Each item states which artifact(s) it applies to; a check scoped to issue bodies also applies to a discussion opening post. A voice-pack skill may add its own checks; run those after this list, never instead of it.

A grep either matches or it doesn't, so run it as an actual command against the actual text, not "I re-read it and it looks fine." A judgment check has no regex; that means read carefully, not skip it. Each check names the rule it enforces, fix a hit the way that rule describes.

## Mechanical checks (run the command, don't eyeball it)

Use the OS's own tools: `grep -E` on Linux/macOS, `Select-String` on Windows PowerShell. Not `rg`, it isn't preinstalled. Applies to everything unless noted.

The commands need a file on disk. For a body headed to `update_pull_request` or another structured tool, write the draft to a temp file first.

- Narrative/historical tells: `grep -inE '(removed|used to|previously|no longer|was updated|a scan found|as of #)' file` / `Select-String -Pattern '(?i)\b(removed|used to|previously|no longer|was updated|a scan found|as of #)\b' file`. Rewrite a hit to describe the system as it is now, or delete the line, per `references/docs-and-comments.md`. Applies to docs and code comments, even when this skill wasn't the reason you opened the file.
- Hand-constructed issue URL: `grep -nE 'pull/[0-9]+#issue-' file` / `Select-String 'pull/\d+#issue-' file`. `SKILL.md` Formatting's issue-references rule.
- Missing owner/repo prefix: `grep -nE '(^|[^a-zA-Z0-9_./-])#[0-9]+' file` / `Select-String '(^|[^a-zA-Z0-9_./-])#\d+' file` for a bare `#123`, and `grep -nE '[a-zA-Z][a-zA-Z0-9_.-]*#[0-9]+' file` / `Select-String '\b[a-zA-Z][a-zA-Z0-9_.-]*#\d+\b' file` for an owner-less `reponame#123`. The second pattern can't see across a `/`, so it also matches the tail of a correct `owner/reponame#123`: a hit preceded by `/` isn't a finding. `SKILL.md` Formatting's issue-references rule.
- Backticked issue reference, whole or partial: `` grep -nE '`#[0-9]+|#[0-9]+`' file `` / `` Select-String '`#\d+|#\d+`' file ``. Catches `` `owner/repo#123` `` and the partial `` `owner/repo`#123 ``, which the previous check can't see. `SKILL.md` Formatting's issue-references rule.
- Non-closing issue phrasing: `grep -inE '(part of|relate[sd]? to).*#[0-9]+' file` / `Select-String -Pattern '(?i)\b(part of|relate[sd]? to)\b.*#\d+' file`. Every hit gets rewritten per `references/pr-writing.md`'s Issue references. Then confirm a closing keyword exists: `grep -inE '(fixes|closes|resolves)' file` / `Select-String -Pattern '(?i)\b(fixes|closes|resolves)\b' file`; zero hits means the PR needs an issue to close. Applies to PR bodies.
- Bare URLs: `grep -nP '(?<!\]\()https?://' file` / `Select-String '(?<!\]\()https?://' file` (`-P`, not `-E`, for the lookbehind). Check each hit by eye: a reference-style link or a URL in a code span slips past the lookbehind, and a bare GitHub issue/PR URL or line-anchored code permalink (`/blob/<sha>/...#L10-L20`) is allowed. `SKILL.md` Formatting's link rule.
- Backtick pileup: `` grep -nE '(`[^`]+`,[[:space:]]*){3,}`[^`]+`' file `` / `` Select-String '(`[^`]+`,\s*){3,}`[^`]+`' file ``. `SKILL.md` Formatting's backtick-pileup rule.
- Decorated review-comment labels: `` grep -nE '^[[:space:]]*(\*\*|`)(praise|nitpick|suggestion|issue|question|thought|chore|note)' file `` / `` Select-String '^\s*(\*\*|`)(praise|nitpick|suggestion|issue|question|thought|chore|note)' file ``. Also confirm the comment opens with a label at all. `references/review-comments.md`. Applies to PR review comments.
- Missing AI watermark: `grep -c '<!--:robot:-->$' file` / `Select-String '<!--:robot:-->$' file`. Zero hits, or a hit that isn't the last line, fails. `references/pr-writing.md`'s AI watermark. Applies to PR bodies and PR/review comments only.
- Hard-wrapped paragraphs: `grep -vE '^([[:space:]]*([#>*-]|[0-9]+\.|\||\`\`\`)|[[:space:]]*$)' file | awk '{ if (length($0) < 90) print NR": "$0 }'` / `Get-Content file | Where-Object { $_ -notmatch '^\s*([#>*-]|\d+\.|\||```)' -and $_.Trim() -ne '' -and $_.Length -lt 90 }`. Flags short prose lines outside headings, lists, quotes, tables, and fences; a genuinely short one-line paragraph is a false positive. `SKILL.md` Formatting's hard-wrap rule. Applies to PR bodies, issue bodies, and docs.
- Verify what landed: after any `gh api`, `gh pr comment`, `gh issue comment`, or `gh discussion comment` post or edit, re-fetch the live body and diff it against the draft, and confirm a closing reference actually linked, per `references/gh-cli.md`'s Verifying what landed. Applies to PR bodies, PR/review comments, issue comments, and discussion comments.
- Body length: `(Get-Content -Raw file).Length` on Windows, `wc -c < file` elsewhere, after deleting fenced ` ```mermaid ` blocks. Compare against the length ceiling in `references/body-writing.md`, and fix it the way that section describes, never by narrowing scope. Applies to PR bodies and issue bodies.
- Over-quoted anticipated-reviewer question: `` grep -Pzo '(?ms)^>.*\?[ \t]*\n>[ \t]*\n>' file `` / `` (Get-Content -Raw file) -match '(?ms)^>.*\?[ \t]*\r?\n>[ \t]*\r?\n>' ``. Matches a quoted question followed by a quoted answer; a `> [!NOTE]` admonition doesn't false-positive. `references/body-writing.md`'s Anticipated reviewer questions. Applies to PR bodies and issue bodies.
- Long comment blocks: `` awk '/^[[:space:]]*<token>/{if(c==0)s=NR;c++;next}{if(c>4)print s"-"(NR-1);c=0}END{if(c>4)print s"-"NR}' file `` / `` $c=0;$s=0;$i=0; Get-Content file | ForEach-Object{$i++; if($_ -match '^\s*<token>'){if($c -eq 0){$s=$i};$c++}else{if($c -gt 4){"$s-$($i-1)"};$c=0}}; if($c -gt 4){"$s-$i"} ``, with `<token>` set to the file's regex-escaped line-comment marker (`\/\/`, `#`, `--`, `;`, `%`). Prints each run of 5+ comment lines, over the cap in `references/docs-and-comments.md`. It can't see `/* */` blocks or docstrings, and a license header or commented-out code is a false positive. Applies to code comments.

## Judgment checks (no regex substitutes for reading it)

- Re-check every testing/verification claim against the diff as it stands now; later edits make claims stale without touching the sentence. An unverified claim counts as a false one. Applies to PR bodies.
- Count the paragraphs before the body's last section (`## Testing`, or the last template section) in the assembled text, against the paragraph ceiling in `references/body-writing.md`. Admonitions and one-liners push it over unnoticed. Applies to PR bodies and issue bodies.
- Scan for asides in the main narrative ("also fixed", "while I was in there", "noticed", a change unrelated to its paragraph) and move them under a `Bonus`/`Chores`/`Also fixed` sub-header per `references/body-writing.md`. Applies to PR bodies and issue bodies.
- Read every top-level bullet in a flat list on its own. One running 3+ sentences, or stacking a mechanism, rationale, and issue reference, needs nested sub-bullets per `SKILL.md` Formatting; a trailing "It exists for..."/"Filed as..." sentence is the tell. Applies to PR bodies and issue bodies.
- Gauge altitude against diff size: a large PR strung with backticked function and variable names needs rewriting a layer up, per `references/body-writing.md`. Applies to PR bodies.
- Scan against `references/banned-phrases.md`. Replace a hit with the concrete thing or delete it; a word inside an identifier or quoted error string isn't a hit. Applies to everything.
- Check the ratio: a comment longer than its code, or a body longer than its diff or ask, usually means a paragraph defending a decision. Clarify the code or cut the explanation. `SKILL.md`'s Never trim these list is exempt. Applies to code comments, PR bodies, and issue bodies.
- When the PR adds or changes a doc, compare each body paragraph to that doc. A paragraph repeating a section of it becomes a gist plus a named branch-ref link, per `references/body-writing.md`'s Docs the PR already carries. Applies to PR bodies.
- Confirm any "not covered here" note surfaces something a linked issue doesn't already show, per `references/body-writing.md`. Applies to PR bodies and issue bodies.
- For every issue/PR number in a code comment, confirm it's an upstream bug or a posterity `TODO`, not planned or in-flight work, per `references/docs-and-comments.md`. Applies to code comments.
- When there's wider context (a parent effort, a prior decision, an outside constraint), confirm it's in a `## Context` section at the top, per `references/body-writing.md`. Applies to PR bodies and issue bodies.
- Check `## Testing` against the repo's CI config: cut any line CI reruns on this PR anyway, per `references/pr-writing.md`. Applies to PR bodies.
- For every "couldn't test X" line, name the concrete test, script, or documented manual step it refers to. None means an invented bar, delete the line per `references/pr-writing.md`. Applies to PR bodies.
